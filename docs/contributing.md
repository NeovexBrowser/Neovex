## Communication

Before big changes:

- Discuss ideas first
- Check existing issues
- Coordinate with maintainers

Keep things clear and relevant.

---

## Design docs

Write a design doc for:

- New features
- Core changes
- Large refactors
- Long work (>1 week)

Include:

- Problem
- Solution
- Alternatives
- Risks
- Rollout plan

---

## Legal

By contributing:

- Your code is original or properly licensed
- You have rights to submit it
- You agree to Neovex licensing (TBD)

A CLA may be required.

---

## First-time contributors

- Add yourself to `AUTHORS`
- Keep first PR small
- Follow existing style

---

## Setup

Clone the repo and install dependencies:

git clone https://github.com/<your-username>/neovex.git  
cd neovex  
npm install  
npm run dev  

---

## Creating a change

Create a new branch:

git checkout -b my-feature  

Make changes and commit:

git commit -m "Add: short description"  

---

## Uploading

Push your branch:

git push origin my-feature  

Then open a Pull Request on GitHub.

---

## Code review

- Maintainers review PRs
- Address feedback
- Keep discussion technical

---

## Tests

Run tests before submitting:

npm test  

Must pass before merge.

---

## Commit style

Good:

Fix: handle empty input safely

Bad:

update code

---

## Guidelines

- Keep code simple
- Follow existing patterns
- Avoid duplication
- Don’t over-engineer

---

## Merging

- Requires approval
- CI must pass
- Maintainers merge

---

Follow Neovex Code of Conduct.
